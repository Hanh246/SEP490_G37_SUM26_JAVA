# 🤖 AI Generation Rules / Quy Tắc Tạo Code Cho AI (Gen AI)

> [!IMPORTANT]
> **MANDATORY**: Any AI agent, coding assistant, or generator (such as Cursor, Copilot, Gemini, Antigravity, etc.) **MUST** read and adhere to these rules before generating, modifying, or refactoring any code in this repository.
> 
> **BẮT BUỘC**: Tất cả AI agent, trợ lý lập trình hoặc công cụ sinh code **PHẢI** đọc và tuân thủ các quy tắc này trước khi viết, sửa đổi hoặc cấu trúc lại bất kỳ mã nguồn nào trong dự án này.

---

## 🚫 1. Do Not Delete/Edit Existing Code / Không Xóa Hoặc Chỉnh Sửa Code Của Người Khác
- **English**: Never delete, overwrite, or edit core business logic, files, or structures created by other developers. 
- **Vietnamese**: Tuyệt đối không xóa, viết đè hoặc chỉnh sửa trực tiếp logic nghiệp vụ, các file hoặc cấu trúc core được viết bởi lập trình viên khác.
- **Action**: If changes are needed, write new files, extend existing classes, or override methods.
- **Hành động**: Nếu cần thay đổi, hãy tạo file mới, kế thừa class cũ hoặc override các method.

---

## 🏗️ 2. Extend Existing Base Structures / Sử Dụng & Kế Thừa File Base Có Sẵn
- **English**: Leverage the predefined base architecture of the project (e.g., `BaseEntity`, `BaseController`, `AbstractCrudRepository`, `AbstractMapperPlugin`, `BaseResponse`) to keep code concise and standardized.
- **Vietnamese**: Luôn luôn tận dụng các cấu trúc base có sẵn của dự án (như `BaseEntity`, `BaseController`, `AbstractCrudRepository`, `AbstractMapperPlugin`, `BaseResponse`) để kế thừa, giúp mã nguồn gọn gàng và đồng bộ.
- **Action**: When creating new entities, they must extend `BaseEntity` (using UUID v7 primary keys). Repositories must extend `AbstractCrudRepository`. Controllers must extend `BaseController`.
- **Hành động**: Khi tạo entity mới, phải extends từ `BaseEntity` (sử dụng khóa chính UUID v7). Repository kế thừa `AbstractCrudRepository`. Controller kế thừa `BaseController`.

---

## 🔄 3. Entity-DTO Mapping Rules / Quy Tắc Ánh Xạ Entity - DTO
- **English**: Use `ModelMapper` for mapping between Entities and DTOs by subclassing `AbstractMapperPlugin`.
- **Vietnamese**: Sử dụng `ModelMapper` để chuyển đổi qua lại giữa Entity và DTO bằng cách tạo plugin kế thừa từ `AbstractMapperPlugin`.
- **Action**: 
  - Subclass `AbstractMapperPlugin<MODEL, DTO, ID>` for your component mapping.
  - Override mapper methods such as `toDto(model)`, `toModel(dto)`, or `performCustomUpdate(existingModel, dto)` to perform custom translation logic that `ModelMapper` cannot resolve automatically.
- **Hành động**:
  - Kế thừa `AbstractMapperPlugin<MODEL, DTO, ID>` cho từng component tương ứng.
  - Override các method ánh xạ như `toDto(model)`, `toModel(dto)`, hoặc `performCustomUpdate(existingModel, dto)` khi cần xử lý các trường dữ liệu tùy biến mà `ModelMapper` không tự động map được.

---

## 🇬🇧 4. English as Primary Language / Sử Dụng Tiếng Anh Cho Thông Điệp & Nội Dung
- **English**: Because this project aims to support an international audience, all code, comments, validation messages, exceptions, logs, email contents, response payloads, and API status messages **MUST** be written in English. Vietnamese is strictly prohibited in any user-facing or log messages.
- **Vietnamese**: Vì dự án hướng tới sử dụng ngôn ngữ quốc tế, toàn bộ mã nguồn, chú thích (comments), thông báo kiểm tra dữ liệu (validation messages), thông điệp lỗi (exceptions), nhật ký (logs), nội dung email, dữ liệu phản hồi (responses) và API messages **BẮT BUỘC** phải viết bằng Tiếng Anh. Tuyệt đối không dùng Tiếng Việt trong bất kỳ thông điệp nào.

---

## 🔒 5. Sensitive Information / Bảo Mật Thông Tin Nhạy Cảm
- **English**: Never commit passwords, API secret keys, database credentials, or private configuration values directly. Load them dynamically using `Dotenv` from `key.env` and reference them via Spring Boot placeholders (e.g. `${JWT_SECRET}`).
- **Vietnamese**: Tuyệt đối không commit mật khẩu, khóa bí mật API, tài khoản cơ sở dữ liệu lên Git. Nạp các khóa này động qua `Dotenv` từ file `key.env` cục bộ và tham chiếu trong `application.properties` bằng placeholders (ví dụ: `${JWT_SECRET}`).

---

## 🎨 6. Styling Files Location / Vị Trí Lưu Trữ CSS
- **English**: All styling sheets (CSS files) **MUST** be placed in the `src/assets/style` directory of the frontend project to maintain structure cleanly. Do not create styling files directly in `src` or `components`.
- **Vietnamese**: Tất cả các file styling (file CSS) **BẮT BUỘC** phải được đặt trong thư mục `src/assets/style` của dự án frontend để giữ cấu trúc dự án sạch sẽ. Không tạo trực tiếp các file style trong thư mục `src` hay `components`.
